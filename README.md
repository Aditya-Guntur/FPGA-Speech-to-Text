# Hear-it-Right

A speech keyword-recognition pipeline implemented directly in Verilog for
the Digilent Cora Z7 (Zynq-7000), from raw PCM audio in BRAM through to a
10-keyword classification shown on an RGB LED. No vendor IP blocks or HLS -
every stage (DSP and neural network both) is hand-written RTL.

## Pipeline

```
audio.mem (BRAM) --> preprocessing --> fft --> mel_filterbank -->
  segment_buffer (gated by onset_trigger) --> gain_normalize --> dense_hidden -->
  relu (x16) --> matrix_multiplication --> relu (x8) --> softmax_lut -->
  argmax --> debounce --> keyword_id / RGB LED
```

| Stage | Module | What it does |
|---|---|---|
| 1 | `preprocessing.v` | Streams 16-bit PCM samples out of a BRAM-backed buffer (`audio.mem`, 21760 samples / ~1.36s at 16kHz) and applies first-order pre-emphasis (`y[n] = x[n] - 0.95*x[n-1]`) to boost high frequencies before analysis. |
| 2 | `fft.v` | Maintains a 64-tap sliding analysis window, applies a Hamming window, then computes a direct-form DFT (`X[k] = sum_n w[n]*x[n]*e^{-j2*pi*k*n/64}`) over 32 positive-frequency bins. Outputs real part (bins 0-31) and imaginary part (bins 0-31) on the same 64 output ports. |
| 3 | `mel_filterbank.v` | Converts each (real, imaginary) bin pair to a magnitude estimate (`\|re\| + \|im\|`), then applies a 13-band triangular Mel filterbank (`mel_filter.mem`, generated by `scripts/generate_mel_filter.py`) to produce 13 Mel features per sample. |
| 4 | `onset_trigger.v` | Watches the raw audio feeding `fft.v` for a short-time energy threshold crossing (256-sample blocks) and holds `segment_buffer.v` idle until it fires, so the classifier's window starts on the spoken word instead of on however much silence happens to precede it in the recording. |
| 5 | `segment_buffer.v` | Pools the streaming per-sample Mel output into 6 segments of ~2048 cycles each (a window long enough to span a spoken word), giving the classifier 78 features (6 segments x 13 bands) that capture how the word's spectrum evolves over time, instead of 13 features describing only the current instant. |
| 6 | `gain_normalize.v` | Approximates dividing the 78 segment-pooled features by their own total energy (a priority encoder finds the highest set bit, then a saturating shift brings it toward a fixed reference magnitude), so two recordings of the same word at different volumes land on similar features. |
| 7 | `dense_hidden.v` | First classifier layer: 78 segment-pooled, gain-normalized Mel features -> 16 hidden units (`hidden_weights.mem` / `hidden_biases.mem`). |
| 8 | `relu.v` (x16) | Hidden-layer ReLU activation. |
| 9 | `matrix_multiplication.v` | Second classifier layer: 16 hidden units -> 8 class scores (`weights.mem` / `biases.mem`). |
| 10 | `relu.v` (x8) | Output-layer ReLU activation. |
| 11 | `softmax_lut.v` | Converts the 8 class scores to probabilities via a precomputed exponential lookup table (`softmax_lut.mem`), with max-subtraction for numerical stability. |
| 12 | `top_module.v` | Argmax over the 8 probabilities selects `raw_keyword_id`. |
| 13 | `debounce.v` | Holds a classification steady for `DEBOUNCE_TIME` clock cycles before it's accepted, filtering out rapid flicker between classes. |

All fixed-point arithmetic is Q1.15 (signed 16-bit, `>>>15` rescale after a
multiply) for weights/activations and Q8 (`>>>8`) for Mel filter
coefficients.

## Output mapping

`keyword_id` (4 bits) drives both an output port and the Cora Z7's onboard
RGB LED (`led_r`, `led_g`, `led_b`):

| `keyword_id` | Keyword | LED |
|---|---|---|
| 0 | Up | Off |
| 1 | Down | Red |
| 2 | Right | Green |
| 3 | Left | Blue |
| 4 | Stop | Yellow |
| 5 | Go | Cyan |
| 6 | Yes | Magenta |
| 7 | No | White |

The classifier only has 8 output classes, so `keyword_id` values 8 (reserved,
blinking red) and 9 (reserved, blinking green) in `top_module.v`'s LED case
statement are unreachable with the current layer sizes - kept for a future
10-class classifier.

## FPGA setup (Digilent Cora Z7)

`constraints.xdc` maps the design to these pins:

| Signal | Pin | Function |
|---|---|---|
| `clk` | K17 | 100MHz onboard oscillator |
| `rst` | D19 | BTN0 |
| `led_r` / `led_g` / `led_b` | M14 / N15 / L14 | Onboard RGB LED (LD4) |
| `keyword_id[3:0]` | Y19 / Y16 / Y17 / W14 | PMOD JB |

Build with Vivado using the included `tcl` script (`opt_design` ->
`place_design` -> `phys_opt_design` -> `route_design`), or run it
interactively: create a project targeting the Cora Z7, add all `.v` files
and `constraints.xdc`, then run synthesis, implementation and generate a
bitstream as usual.

## Simulating

Every module has its own testbench. With [Icarus
Verilog](http://iverilog.icarus.com/):

```bash
# Any single stage, e.g. the DFT
iverilog -o fft.vvp fft_tb.v fft.v
vvp fft.vvp

# The full pipeline
iverilog -o top.vvp top_module_tb.v top_module.v preprocessing.v fft.v \
    mel_filterbank.v onset_trigger.v segment_buffer.v gain_normalize.v \
    dense_hidden.v matrix_multiplication.v relu.v softmax_lut.v debounce.v
vvp top.vvp
```

`$readmemh` loads every `.mem` file relative to the simulator's working
directory, so run these from the repo root.

## Regenerating the `.mem` files

- **`scripts/generate_mel_filter.py`** builds `mel_filter.mem` from a
  standard Mel-scale triangular filterbank formula, sized for the hardware's
  actual bin/band count (`--bins`/`--bands`).
- **`scripts/init_weights.py`** writes default-initialized
  `hidden_weights.mem` / `hidden_biases.mem` / `weights.mem` / `biases.mem`.
- **`scripts/decimal_to_hex_mem.py`** converts a plain signed-decimal `.mem`
  file (one value per line) to the 16-bit hex format `$readmemh` actually
  requires.
- **`scripts/extract_features.py`** reproduces the hardware's exact signal
  path (pre-emphasis -> Hamming window -> DFT -> magnitude -> Mel
  filterbank -> onset alignment -> segment pooling -> gain normalization)
  in floating-point Python/numpy, for inspecting features outside
  simulation. `extract_segments` matches `onset_trigger.v` +
  `segment_buffer.v` + `gain_normalize.v` exactly: `onset_align` scans
  forward in the same 256-sample blocks `onset_trigger.v` does for the
  first one whose energy crosses the same calibrated threshold, then
  `extract_segments` mean-pools 6 equal chunks of frames from that point
  and applies the same priority-encoder-based gain normalization.
- **`scripts/train.py`** trains the two-layer classifier on a directory of
  labeled recordings and exports the result straight to the `.mem` layout
  above:

  ```bash
  python scripts/train.py data/ --classes up down right left stop go yes no
  ```

  expects `data/<keyword>/*.wav` (16kHz mono 16-bit PCM) for each of the 8
  classes above. Besides the onset/segment/gain feature pipeline above,
  it also standardizes the 78 features before training (folding that
  back into the hidden layer's weights afterward so the exported `.mem`
  files still expect raw, unstandardized input - raw filterbank output is
  badly scaled for gradient descent on a network this small) and
  augments the training set with time-shifted, lightly noised copies of
  each clip (evaluated only on clean, un-augmented held-out audio).

mirrors from the hardware (32-bin DFT, onset alignment, 6-segment
pooling, gain normalization - see the Pipeline table above), plus
time-shift/noise augmentation during training only. Held-out accuracy
on an 80/20 split of clean, un-augmented audio is 0.713 (vs. 0.125 for
random guessing across 8 classes). Confusion matrix and training loss
curve for that run:

This model went through four real rounds of improvement, each change
verified by actually measuring held-out accuracy rather than assumed:

1. **Whole-clip mean-pooling -> 6-segment pooling** (`segment_buffer.v`):
   averaging every frame of a ~1s clip into a single 13-feature vector
   capped held-out accuracy around 0.36 regardless of how much training
   data or how elaborate the training method (standardization,
   knowledge distillation from a bigger teacher model) was thrown at
   it. That ceiling tracks a documented failure mode in small-footprint
   keyword-spotting literature: Zhang et al.'s "Hello Edge: Keyword
   Spotting on Microcontrollers" points out that plain DNNs trained on
   pooled or flattened per-frame features discard local temporal
   correlation that convolutional/recurrent models exploit.
   `segment_buffer.v` is this project's hand-written-RTL answer to that
   - not a conv/recurrent layer, but enough of a sliding temporal
   window (6 segments instead of 1) to take held-out accuracy to ~0.51.
2. **Per-utterance gain normalization** (`gain_normalize.v`): two
   recordings of the same word at different volumes landed on very
   different segment-pooled features, which the classifier had no way
   to tell apart from an actual difference in content. A
   priority-encoder-based shift that approximates dividing by each
   utterance's own energy took held-out accuracy to ~0.55.
3. **Onset-triggered windowing** (`onset_trigger.v`): real recordings
   pad the spoken word with a variable amount of silence, so starting
   the 6-segment window at sample 0 of every clip means the word lands
   in a different segment on every recording - noise the classifier
   had no way to average out. Gating `segment_buffer.v` on a
   short-time energy threshold crossing, rather than always starting
   from sample 0, took held-out accuracy to ~0.60, without needing to
   see the whole clip in advance (which a real-time streaming design
   can't do - centering on a clip's single loudest point, which does
   require that look-ahead, reached ~0.69 in testing but isn't
   something this hardware can do).
4. **8-bin DFT -> 32-bin DFT** (`fft.v`, `mel_filterbank.v`): by far
   the largest single change. 8 frequency bins across the full 8kHz
   Nyquist range (~1kHz/bin) is too coarse to resolve much of speech's
   actual spectral structure - every other change up to this point was
   about removing *noise* from a fixed amount of frequency information;
   this one adds more of that information in the first place. Doubling
   the DFT size twice (8 -> 16 -> 32 bins, `fft.v`'s direct-form DFT
   cost grows as taps*bins) took held-out accuracy from ~0.60 to
   ~0.71-0.72; a further doubling to 64 bins only added ~0.01 more for
   4x the hardware cost, so 32 was kept as the better tradeoff.

An 8-way classifier built from a 13-band Mel/32-bin DFT front end and a
78→16→8 MLP is still a tight budget for real speech - the point of this
project is the hand-written RTL pipeline end-to-end (BRAM to LED), not
state-of-the-art keyword spotting accuracy. More bins, more segments, a
buffered (non-causal) onset window, or a bigger hidden layer (all just
module/`.mem` size parameters, in the spirit of the four changes above)
would likely push accuracy further.
